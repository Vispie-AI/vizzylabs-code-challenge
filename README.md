# 创作工作区：UI 一致性问题排查

Lantern Studio 是一个面向内容创作者的网页工作台。用户会在工作区里编辑场景备注、运行预览、查看工作区信息；有些用户会长时间保持页面打开，在多个标签页之间切换。团队会持续发布界面更新，用户希望更新期间也能继续手头的创作。

最近收到用户反馈：更新后，有些页面的 UI 元素、样式和布局不一致。同一个工作区，已经打开的页面和新打开的页面有时看起来不同；部分页面的界面不完整，正在编辑的内容也受到影响。

你是刚接手这个项目的全栈工程师。请从这些反馈出发，自行理解项目、复现问题并排查定位，给出有依据的解决方案，完成你认为两小时内最重要的修改与验证。需要哪些信息、如何缩小排查范围、在哪里修改，都由你判断；尚未确认的判断请说明。

本仓库是为面试独立编写的演练环境，使用虚构内容，不需要访问公司内部系统。

## 环境准备

需要 Node.js 22.15 或以上、npm，以及首次下载公开依赖的网络。建议使用 Node.js 24。

```sh
npm ci
npm run setup
npm start
```

打开启动日志中给出的完整本地访问链接。另一个终端执行：

```sh
npm run check
```

看到 `Environment ready` 后开始计时。此命令只确认环境可用，不代表报告的问题已经解决。首次安装可能需要几分钟；环境准备不计入作业时间。遇到安装或启动障碍，可以保留错误信息并联系我们。

首次打开若出现 **Preview Notice**，点击 **Continue**，再关闭 **Get started** 弹窗（右上角 × 或 Esc）。工作区内可编辑 **Scene notes**，运行 **Run preview**，查看 **Workspace details**。这些操作不需要配置模型或外部服务。

开发环境提供两套工作区发布版本。服务运行时可在另一终端切换：

```sh
npm run release -- two
npm run release -- one
```

`npm run reset` 将发布状态恢复为 `one`。可通过 `PORT=3082 npm start` 更改端口，对应自检使用 `CHALLENGE_URL=http://127.0.0.1:3082 npm run check`。修改客户端源文件后执行 `npm run build`，停止服务后重新执行 `npm run setup` 和 `npm start`。

## 需要达到的用户结果

- 工作区正常加载，原有操作仍可使用。
- 发布更新后，用户看到完整、一致的界面，页面上的主要操作可以继续使用。
- 更新不能导致用户未提交的编辑内容丢失，或使正在进行的工作被意外打断。
- 完成发布后，新打开的页面可以使用相应版本。重复发布或回到之前版本时，基本操作仍成立。
- 有可复现的验证来覆盖报告的现象和你的改动。

请在现有应用中完成修改，保留上述业务操作。可以调整本仓库内的实现、结构和测试；不需要新增模型功能、账户系统或生产部署。现场会给出一项明确的用户约束，到时会说明；未公布的扩展要求不影响作业评分。

## 时间与提交

收到题目后五个自然日内，安排最多两小时。阅读、修改、测试和交接说明计入两小时；到时可以停止，说明现状。额外功能和超时投入不加分。

提交代码、相关测试、实际投入时间，以及不超过一页的 `NOTES.md`：

1. 用几句话给 PM 说明用户影响、现在的结果和剩余限制。
2. 给接手的工程师说明你对项目的理解、问题的复现方式与定位依据、方案取舍、改动、实际执行的验证及下一步。请区分已验证的结论和仍需确认的假设。
3. 说明 AI 工具的使用方式，以及一项你核验或修正过的建议。未使用 AI、没有遇到错误建议，都可如实说明。

欢迎使用 AI。你需要能解释和验证自己的提交；无需提供完整聊天记录、私人账户信息或录屏。后续有约六十分钟的演示、现场续作和交接：其中开头五分钟先自行预测行为，可以阅读代码和文档，暂不使用 AI；后续可以继续使用。

启动日志、`node_modules/` 及 `.gitignore` 中排除的运行数据无需提交。
